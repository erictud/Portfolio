## Creating Objects

### Declaration

Declares a **reference variable** of a specific class type:
```java
ClassName objectName;
```

### Instantiation

Uses the `new` keyword to allocate memory dynamically on the **heap** for the new instance:
```java
objectName = new ClassName();
```

### Initialization

Invokes the **constructor** with the appropriate arguments, populating the object's instance fields with initial state.
Initialization can also use **anonymous objects** (*objects instantiated without saving their reference to a distinct variable*):
```java
objectName = new ClassName(arg1, arg2, arg3, new ClassName() /* anonymous object */);
```

> **Important**
> Declaring a variable **does not** allocate an object in memory. Attempting to access its instance fields or methods before assignment triggers a **compilation error** (for local variables) or a `NullPointerException` at runtime (for unassigned reference fields).
>
> ```java
> Car bmw;
> bmw.horsepower = 100; // Compilation error: variable bmw might not have been initialized
> ```

## Using Objects

### Accessing Fields and Methods

Instance members are accessed using the **dot operator (`.`)**:
```java
objectName.field;
objectName.method(arg1, arg2);
```

To guard against **invalid states**, OOP applies **encapsulation**. By marking fields with access modifiers such as `private` or `protected`, **direct external modification and reading are blocked**. State transitions are mediated safely using accessor and mutator methods (**getters** and **setters**):

```java
class Car {
    private int horsepower;

    // Mutator (setter)
    public void setHorsepower(int value) {
        if (value <= 0) {
            return; // Reject invalid mutations
        }
        this.horsepower = value;
    }
}
```

## Destroying Objects

Java is a **garbage-collected language**, meaning the runtime automatically reclaims an object's heap memory once that object is **no longer reachable** by any active execution path.

References are typically detached in two ways:
- **Naturally** — when a reference variable **falls out of scope**.
- **Explicitly** — by deliberately assigning `null` to the reference variable.

Memory deallocation is handled by the **Garbage Collector (GC)**, an autonomous daemon process within the **Java Virtual Machine (JVM)** that tracks unreachable objects and releases their allocated memory.

> Explicit invocation via `System.gc()` merely submits a **suggestion** to the JVM. It provides **no guarantee** that the garbage collector will run immediately or reclaim memory on demand.

### The `finalize()` Method

Historically, before reclaiming an object's memory, the garbage collector would invoke the `finalize()` method declared in the `java.lang.Object` root class.
Its original purpose was to release **non-heap system resources** (e.g., file descriptors, sockets). However, `finalize()` has been deprecated because the timing of GC sweeps is **completely non-deterministic**.

```java
@Override
protected void finalize() throws Throwable {
    // Deprecated cleanup logic
}
```

## Declaring a Class

The standard structural definition of a Java class follows this syntax:

```java
[public] [abstract | final] class ClassName extends SuperClassName 
    implements Interface1, Interface2 {
    // Class body: fields, constructors, methods, and nested classes
}
```

Java enforces that all **methods**, **instance fields**, **constructors**, and **nested types** reside directly within the enclosing class body. It supports **inheritance**, enabling a **subclass (derived class)** to inherit all *non-private fields and methods* from its **superclass (base class)**, with the option to *override* inherited behaviors.

### Single Inheritance

Java enforces **single class inheritance**; a class may extend **only one direct superclass**, which prevents the structural ambiguities of the **Diamond Problem** (*conflicts arising from inheriting duplicate method signatures from multiple parents*). Multiple structural subtyping is supported exclusively via **interfaces**.

### `abstract` Classes

An **`abstract` class** is a restricted class that **cannot be directly instantiated** using `new`. It serves as a foundational blueprint that mandates subtyping, defining shared state and behavior while leaving concrete details to its subclasses:
- Can declare **abstract methods** (*signatures without a method body*), forcing subclasses to supply the implementation.
- Can contain fully implemented **concrete methods**.
- Can define **constructors**, which execute through *constructor chaining* when concrete subclasses are instantiated.

### `final` Classes

A class declared with the `final` modifier **cannot be extended**. It sits at the opposite extreme of an abstract class (*an abstract class requires extension to be utilized, whereas a final class strictly forbids inheritance*):
- All methods inside a `final` class are implicitly incapable of being overridden, securing classes such as `java.lang.String` against tampering.

## The `Object` Class

`java.lang.Object` is the **root class** of the entire Java type hierarchy. Every Java class implicitly extends `Object` if no explicit superclass is declared, inheriting core methods:

* `equals(Object obj)` — by default, compares references using the `==` operator (**memory address identity**, rather than value equality). It must be explicitly overridden to establish semantic **content equality**.
* `hashCode()` — generates an integer hash for hash-based data structures.

> **Best Practice:** Always override `hashCode()` whenever overriding `equals()` to uphold the contract required by collections such as `HashMap` and `HashSet`.

* `toString()` — returns a string representation of the object. Java invokes `toString()` automatically when an object reference is concatenated with a `String` or passed to output streams like `System.out.println()`.
* `clone()` — defined on instances implementing the `Cloneable` interface. By default, it yields a **shallow copy**: primitive fields are copied by **value**, while reference fields copy only the **pointer addresses**, meaning original and cloned instances reference identical nested objects on the heap.

## Constructors & Default Initialization

A **constructor** is a dedicated initialization block invoked automatically whenever an instance is created via `new`. Its duty is to establish **valid initial state** by assigning field values before the instance reference is returned.

Constructor characteristics:
- Must match the **exact name of the class**.
- Has **no return type** (not even `void`).

If a class defines no constructors explicitly, the Java compiler injects an **implicit default no-argument constructor** that zero-initializes heap-allocated fields:
- `0` or `0.0` for **primitive numeric types** (`byte`, `short`, `int`, `long`, `float`, `double`)
- `\u0000` (null character) for the `char` type
- `false` for `boolean` types
- `null` for all **reference types**

> **Important:** Declaring **any** explicit parameterized constructor suppresses compiler generation of the default no-argument constructor.

Classes can define multiple constructors with unique parameter signatures via **constructor overloading**.

> **Variable Scope Note:** Default initialization applies **only to class-level instance and static fields on the heap**. **Local variables** residing on the stack frame receive no default values; reading an uninitialized local variable causes a **compilation error**.

## The `this` and `super` Keywords

These keywords resolve naming ambiguities and establish explicit parent-child reference links:

* `this` — refers to the **current instance**. Primarily resolves **variable shadowing** (e.g., when a method parameter shares an identifier with an instance field: `this.horsepower = horsepower`).
* `super` — refers to the **immediate superclass context**. Used to call overridden base class implementations (e.g., `super.displayInfo()`).

### Constructor Invocations

- `this(...)` — calls an alternative constructor within the **same class** (useful for constructor telescoping / delegating to a primary constructor).
- `super(...)` — explicitly executes a constructor declared within the **immediate superclass**.

> **Syntax Rule:** Explicit calls to `this(...)` or `super(...)` can occur **only on the very first line** of a constructor body. Consequently, both invocations cannot be combined in the same constructor.

### Constructor Chaining

**Constructors are never inherited by derived classes.** Whenever a subclass is instantiated, the **superclass constructor runs first**, ensuring parent state is initialized before child initialization begins.
If the first line of a child constructor does not contain an explicit call to `this(...)` or `super(...)`, the compiler automatically inserts an invisible, parameterless `super()` invocation.

> If a superclass lacks a visible no-argument constructor, any subclass constructor **fails compilation** unless it supplies an explicit, parameterized `super(args)` on line one.

## Access Modifiers

Access modifiers are reserved keywords defining the scope and visibility of classes, methods, and fields:

| Modifier | Enclosing Class | Enclosing Package | Subclass (External Package) | Global (*Public Access*) |
| :--- | :---: | :---: | :---: | :---: |
| `private` | **Yes** | No | No | No |
| *Package-Private* (*default / no keyword*) | **Yes** | **Yes** | No | No |
| `protected` | **Yes** | **Yes** | **Yes** | No |
| `public` | **Yes** | **Yes** | **Yes** | **Yes** |

> **Top-level classes** (classes not nested inside another class) can only declare `public` or default (*package-private*) visibility.

## Initialization Blocks

Java supports dedicated structural blocks within the class definition to handle non-constructor initialization:

### Static Initialization Blocks (`static { ... }`)

Target class-level state and run **once**, at the moment the JVM loads and initializes the class into memory:
- Executed strictly in the **top-to-bottom sequence** in which they appear in the source code.
- Used to compute static constants or initialize complex class-wide configurations.

### Instance Initialization Blocks (`{ ... }`)

Target instance-level initialization and run **every time a new object is created**:
- The JVM executes instance blocks **after** the superclass constructor completes, but **before** the matching child constructor body executes.
- Useful for sharing state-initialization logic across multiple overloaded constructors.
- Execute sequentially in the order written in the source code.

## Field (Variable) Modifiers

Applied to field definitions: `[modifiers] Type variableName [= initialValue];`

* `final` — marks the field as an immutable assignment that can be **written only once** (at declaration or in the constructor). For **reference variables**, immutability applies to the pointer: *the reference cannot point to another object, though the internal fields of the object itself may remain mutable*.
* `static` — designates a **class variable** belonging to the class type rather than to instances. Only one shared copy exists across all instances, accessed via `ClassName.variableName`. Combining `static final` creates class-level constants.
* `transient` — informs serialization frameworks that the field **must not be persisted** into byte streams (used for sensitive credentials or cache values reconstructible at runtime).
* `volatile` — disables thread-local CPU register caching for the variable. All reads and writes hit **main memory directly**, guaranteeing **visibility** of updates across concurrent threads.

## Method Modifiers

Method declarations follow the general structure:
```java
[modifiers] ReturnType methodName([parameters]) [throws ExceptionType] {
    // Body
}
```

* `static` — defines a **class method** callable directly using `ClassName.methodName()` without instantiating the class (e.g., `Math.sqrt(...)`). Static methods have no instance context and **cannot reference `this` or `super`**.
* `abstract` — defines a signature without a body, forcing concrete subclasses to supply an implementation.
* `final` — prevents derived subclasses from **overriding** the method.
* `synchronized` — restricts execution to a single thread at a time per monitor lock, managing concurrent access to state.
* `native` — designates that the routine is implemented externally in platform-dependent native code (C/C++) via the **Java Native Interface (JNI)**.

## Method Arguments: Pass-by-Value

Java parameters cannot duplicate local variable names declared inside the method scope. They can, however, duplicate instance field names, which are disambiguated using `this.fieldName`.

> **Core Principle:** Java is strictly **pass-by-value**. When calling a method, the JVM makes an independent bitwise copy of the argument value and binds it to the method parameter.

### Memory Differences by Type

1. **Primitive Types (`int`, `double`, `boolean`, etc.):**
   - The variable stores the **literal value** directly on the stack.
   - When passed into a method, the parameter receives a **duplicate copy of the raw bits**. Modifying this parameter leaves the caller's variable untouched.

2. **Reference Types (`String`, `Car`, arrays):**
   - The variable does not store the object itself; it stores a **memory reference (pointer)** pointing to the object located on the **heap**.
   - When passed into a method, Java copies the **reference value (the memory address)**. Both caller and parameter point to the exact same heap allocation.

### Analogy: The House Address

* **Passing a Primitive:** Like copying the number `5` from your notebook onto a sticky note and handing it to a peer. If they cross out `5` and write `99` on their slip, your notebook remains unchanged.
* **Passing an Object Reference:** Like writing your **house address** on a piece of paper and handing it over:
  - **Modifying state:** If your peer follows the address to your house and paints your front door green, the door remains green when you return home—you both share the **same physical house**.
  - **Reassigning the reference:** If your peer erases the address on their paper and writes down a new apartment address, they have merely updated their paper's destination; your original house is unaffected.

## Wrapper Classes

Java pairs every primitive data type with a corresponding reference-type **wrapper class** in the `java.lang` package:

| Primitive Type | Wrapper Class |
| :--- | :--- |
| `byte` | `Byte` |
| `short` | `Short` |
| `int` | `Integer` |
| `long` | `Long` |
| `float` | `Float` |
| `double` | `Double` |
| `char` | `Character` |
| `boolean` | `Boolean` |

> **Immutability:** Every wrapper class instance is **immutable**. Mutating a value creates an entirely **new object** on the heap.

Conversions between primitives and their respective wrapper instances are performed automatically by the compiler via **autoboxing** (primitive to object) and **unboxing** (object to primitive).
